# Golden test vectors

Generated by an independent reference implementation, compared at a relative tolerance of `1e-12`.

**Never hand-edited to make a test pass.** If a golden value looks wrong, say so and stop -- either
the reference or the implementation is wrong, and editing the vector hides which.

# Canary runs

`canaries/` holds the frozen reference runs: a
declarative spec plus expected outputs, replayed by `tests/CanaryTest.m`. The
canary generator `canaries/generateCanary.m` records how each was made.

**The directory now holds two canaries, and they are accepted on different criteria
.** The criterion is a property of the artefact, not of the directory, so a
reference here is never judged by the paragraph above without checking which kind it is.

- `sisoNarxBudget.json` -- the **value** canary. Its solver is `rid.opt.GridSearch`, so
  no toolbox routine appears anywhere in its replay path and every number in it is ours
  end to end. Compared at `1e-12` relative, the golden-vector convention. Its stated cost
  is that it does not exercise the analytic-gradient path.
- `sisoNarxMultiStart.json` -- the **path** canary. The same configuration with
  `rid.opt.MultiStart`, so `fmincon` is knowingly in the replay path and the
  analytic-gradient path is covered. It freezes the **path the run took**: the affine
  tier per surrogate epoch, the gradient path per step, `J` monotone within a segment,
  the reset count, per-step evaluation counts to an order of magnitude, and the final `J`
  inside a band declared in the file. It deliberately stores **no `u`, no `theta` and no
  `J`**, because `J` is not convex and a changed iterate path can land in a different
  local optimum, whereupon the committed input jumps -- no tolerance covers a basin
  switch, and a canary that flaps on a MATLAB upgrade gets switched off. Adding those
  quantities "for strength" is the failure the path canary predicts, not an improvement.

Both are re-recorded only in a commit that touches the canary files alone, with a
one-line reason. A red **path** canary is never a re-recording candidate on the
strength of an upgrade: it reads only what an upgrade cannot legitimately move.
